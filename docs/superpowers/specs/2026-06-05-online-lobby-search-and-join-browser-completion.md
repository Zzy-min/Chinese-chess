# Spec: Online Lobby Search and Join Browser Completion

## Background
- 当前 `/online#/play` 新前端已经呈现搜索框与邀请码加入入口。
- 但现状存在两个浏览器层面的断点：
  - 搜索框是 `readonly` 壳，没有真实查询链路。
  - 邀请码输入框没有接入 `joinByCode()` 读取的 DOM id，按钮在新大厅页不可用。

## Goal
- 让大厅页中“搜索房间、玩家、房间号”和“通过邀请码加入”都成为真实可用的浏览器能力。
- 不引入会员门槛，不改变既有房间创建/加入协议。

## Scope
1. 后端补齐大厅搜索接口
- 新增 `GET /online/api/lobby/search?q=&limit=`
- 返回：
  - `query`
  - `rooms`: 匹配公开房间
  - `players`: 匹配用户名
  - `generatedAt`

2. 搜索语义
- 房间匹配字段：
  - `roomCode`
  - `hostUsername`
  - `guestUsername`
  - `gameType`
- 玩家匹配字段：
  - `username`
- 默认大小写不敏感。
- 空查询直接返回空结果，不做全量扫屏。

3. 浏览器接线
- 大厅搜索框改为可输入。
- 输入时触发查询并展示结果区。
- 点击房间结果：
  - 已在房间内或已开局时，优先跳到对应房间或对局。
  - 其他情况跳到房间页。
- 点击玩家结果跳到排行榜页，至少保证有真实导航反馈而不是死元素。

4. 邀请码加入链路补齐
- 大厅邀请码输入框去掉只读，并补 `id="joinCode"`。
- “通过邀请码加入”按钮继续复用现有 `/online/api/rooms/join-by-code`。
- 成功后跳转房间页；失败显示后端错误。

## Non-Goals
- 本次不做全文社交搜索、模糊推荐、消息系统。
- 本次不改房间协议，不加新的鉴权模型。

## Acceptance
1. 浏览器里可直接输入邀请码并加入房间。
2. 浏览器里输入房间码/玩家名可看到真实查询结果。
3. 搜索结果和加入行为都来自真实后端响应，不靠前端硬编码。
4. 相关接口与浏览器链路有新鲜测试与验收证据。
