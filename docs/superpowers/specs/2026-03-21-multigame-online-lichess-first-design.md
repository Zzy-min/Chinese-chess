# 三棋在线棋站首版设计

## 概要

本项目从“单页本地棋盘 Web 壳”升级为“多棋种在线棋站首版”。

首版目标：

- 借鉴 lichess 的信息架构和交互效率，而不是沿用当前单页游戏化首页。
- 将双人对战从“同终端共享操作”改为“不同终端通过房间邀请实时对战”。
- 保持中国象棋、五子棋、围棋三棋统一站点结构，但首版真实在线链路优先打通象棋和五子棋，围棋保留统一入口和显式能力状态。

首版范围：

- 真实可用：首页、全局导航、对局大厅、房间页、在线对局页、分析页、基础注册登录。
- 高保真占位：观战、社区、排行榜、俱乐部、活动。
- 数据持久化：Postgres。
- 实时协议：WebSocket。

## 产品结构

一级导航固定为：

- 首页 Home
- 对局 Play
- 学习 Learn
- 观战 Watch
- 社区 Community
- 个人 Me

页面职责：

- 首页：三棋入口、在线摘要、快速开始、最近完成对局摘要。
- 对局大厅：创建房间、邀请码加入、棋种筛选、时控和规则选择。
- 房间页：房间码、成员席位、准备状态、开始状态。
- 对局页：棋盘、时钟、走子记录、求和/认输/悔棋请求、系统事件。
- 分析页：走子列表、步进回放、局后结果摘要。
- 学习页：残局/题库/教程入口。
- 观战页：壳层与公开房间占位。
- 社区页：排行榜、俱乐部、活动入口占位。
- 个人页：账户资料、战绩摘要、偏好设置。

## 在线对战模型

首版使用“创建房间/邀请码”进入方式：

- 玩家 A 在大厅创建房间。
- 系统生成房间码和分享链接。
- 玩家 B 通过房间码或链接加入。
- 双方在房间页准备完成后进入对局。
- 房间状态机：`waiting -> full -> ready -> playing -> finished`，异常断开可进入 `abandoned`。

身份方案：

- 首版必须有注册登录。
- 使用 `username + password`。
- 登录后具备固定昵称和对局归属能力。

## 服务端设计

保留现有本地浏览器模式服务器，新增公共在线站点服务器。

新服务器职责：

- 提供站点壳和在线前端资源。
- 提供认证、房间、大厅、分析、个人页摘要 API。
- 提供 WebSocket 实时同步。

核心数据模型：

- `users`
- `auth_sessions`
- `rooms`
- `games`
- `game_moves`

核心运行时模型：

- `RoomRuntime`：维护房间内在线用户与活动对局。
- `OnlineMatch`：抽象三棋在线对局状态。
- `XiangqiMatchEngine` / `GomokuMatchEngine`：基于现有规则引擎实现在线走子。

## 前端设计

不再修改现有单页对局前端作为主站，而是新增在线站点前端壳：

- 顶栏导航、棋种上下文、账户入口固定可见。
- 首页和大厅承担任务分发职责。
- 对局页只保留高频局内操作，不再混入开局配置。
- 分析页独立承接局后回放。

视觉方向：

- Lichess-first。
- 保留少量东方棋类品牌细节，不保留当前重装饰屋檐、仪式化 banner 作为主导。

## 风险与边界

- 当前公共 Web 端没有数据库、认证、WebSocket、多实例共享状态，属于基础设施级增量，不是局部前端重构。
- 现有 `GameController` 依赖 Swing，不适合作为在线公共后端直接复用；在线对局层需要独立实现。
- 围棋在线链路首版允许保持占位或显式未开放状态，但站点结构必须预留完整位置。
