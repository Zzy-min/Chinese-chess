# 账号、持久化与回顾基础设施设计

## 概要

本轮在现有四棋 Node/TS 主站基础上，补齐一条真正可持续扩展的产品基础设施闭环：站内账号体系、PostgreSQL 持久化、历史对局归档、个人页、基础排行榜，以及可回放的回顾页。

本轮的目标不是把“分析”直接做成深度引擎系统，而是先把所有在线局和练习局沉淀成稳定、可查询、可回放、可归属到用户的数据资产。只有这条链路稳定后，后续更深的分析、社区、段位和跨端同步才有可靠基础。

## 目标

- 提供站内账号：注册、登录、登出、基于 cookie 的会话。
- 将当前内存态房间和练习会话升级为持久化状态，服务重启后历史数据不丢失。
- 对在线对局和练习局统一生成归档记录，支持历史页、个人页、排行榜和回顾页复用。
- 提供统一回顾页，支持四棋步进回放、结果摘要、关键节点标签和来源识别。
- 提供个人页，展示用户资料、近期活动、历史对局、练习记录与基础战绩。
- 提供四棋基础排行榜，先做站内积分与统计榜，不直接承诺完整 Elo 或深度匹配评级。

## 非目标

本轮不做：

- 第三方登录。
- 复杂角色权限体系，先只区分游客与登录用户。
- 深度引擎分析、逐步强算、AI 评分类回顾。
- 观战、评论、社交关注、消息中心。
- 跨设备实时恢复未完成活动局的强一致方案。

## 产品边界

### 游客与用户

- 游客可浏览首页、能力面板、部分大厅信息和排行榜。
- 登录用户才能创建房间、加入房间、开始练习、查看自己的完整历史和个人统计。
- 个人页中的公开部分只展示基础战绩摘要；完整历史默认仅本人可见。

### 历史与归档

- 在线对局结束后生成 `game archive`。
- 练习局结束或用户主动退出后生成 `practice archive`。
- 回顾页统一读取 archive，不直接依赖活动房间或活动练习会话。
- 历史页先支持分页列表、按棋种过滤、按来源过滤，不先做全文搜索。

### 排行榜

- 在线对局优先进入排行榜。
- 练习局先进入个人统计，不进入全站主榜；可保留单独练习完成数榜单。
- 首版积分模型以简单可解释为先：胜 +3，和 +1，负 +0；不同棋种分别统计。

## 技术方向

### 数据层

引入 `PostgreSQL + Prisma` 作为主数据层。

原因：

- 本轮核心诉求是持久化、归档、历史查询、用户归属和排行榜聚合。
- 当前内存 store 适合原型验证，但不适合账号、历史、统计、重启恢复。
- Prisma 足以支撑当前关系模型，且和 TypeScript 主站集成成本低。

### 认证

采用站内账号 + 服务端签名会话 cookie。

- 密码使用强哈希存储。
- 浏览器不将 token 存入 `localStorage`。
- 通过 `httpOnly`、`sameSite`、`secure` cookie 维持会话。
- API 通过当前会话识别用户，不把 `userId` 暴露给前端控制写权限。

### 在线局与练习局持久化策略

- 活动房间与活动练习仍可在内存中保留 runtime，以减少实时逻辑复杂度。
- 每次关键状态变更都写入数据库快照与事件记录。
- 对局结束时生成归档记录；活动态与归档态分离。
- 若服务重启，活动态不强制恢复为可继续对局，但已落库的历史、已结束对局和练习记录必须保留。

这意味着“持久化状态”首版重点是历史与用户数据持久化，不承诺中断后恢复一盘未完对局的完整 runtime。

## 核心对象模型

建议新增或明确以下实体：

- `User`
  - 站内用户。
- `Session`
  - 登录会话，和 cookie 绑定。
- `ActiveRoom`
  - 当前活动房间元数据。
- `ActiveMatchSnapshot`
  - 活动在线局快照与走子事件。
- `PracticeSessionRecord`
  - 活动练习局快照与走子事件。
- `GameArchive`
  - 已结束在线对局归档。
- `PracticeArchive`
  - 已结束练习局归档。
- `ReviewRecord`
  - 回顾摘要、关键节点标签、来源说明。
- `LeaderboardEntry`
  - 用户在各棋种的基础统计聚合，可运行时计算或定期写回。

建议数据库表：

- `users`
- `sessions`
- `active_rooms`
- `active_room_participants`
- `active_match_snapshots`
- `active_match_moves`
- `practice_sessions`
- `practice_moves`
- `game_archives`
- `game_archive_moves`
- `practice_archives`
- `practice_archive_moves`
- `review_records`
- `leaderboard_stats`

## 页面设计

### 登录 / 注册

- `/login`
- `/register`

要求：

- 清晰、轻量，不做复杂营销文案。
- 校验即时、错误信息明确。
- 登录后跳回用户原目标页。

### 个人页

- `/me`

展示：

- 昵称、注册时间。
- 四棋基础统计卡片。
- 最近在线对局。
- 最近练习记录。
- 快捷入口：继续练习、查看历史、查看排行榜。

### 历史页

- `/history`

展示：

- 在线对局与练习归档混合列表。
- 过滤项：棋种、来源、结果。
- 每条记录可进入对应回顾页。

### 回顾页

- `/review/[archiveId]`

展示：

- 棋盘回放。
- 走子列表与当前步同步高亮。
- 对局结果摘要。
- 关键节点标签，例如“开局失误”“终局转折”“连续停一手结束”。
- 来源标识：在线对局 / AI 练习。

回顾页首版定义为“高质量回放页”，不是“强分析页”。

### 排行榜页

- `/leaderboard`

展示：

- 棋种切换。
- 在线对局积分榜。
- 胜率、对局数、最近活跃时间。
- 练习局相关统计可作为副榜，不挤占主榜。

## API 设计

### 认证接口

- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/me`

### 用户与历史接口

- `GET /api/me/profile`
- `GET /api/me/history`
- `GET /api/me/practice-history`
- `GET /api/leaderboard?gameType=...`
- `GET /api/reviews/:archiveId`

### 房间与练习改造

在保留现有在线和练习接口的基础上，追加持久化行为：

- `POST /api/rooms`
  - 创建活动房间并写入 `active_rooms`。
- `POST /api/rooms/:roomId/join`
  - 写入参与者。
- `POST /api/rooms/:roomId/start`
  - 初始化活动对局快照。
- `POST /api/rooms/:roomId/move`
  - 写入活动走子事件，并在终局时转归档。
- `POST /api/practice-games`
  - 创建活动练习会话。
- `POST /api/practice-games/:id/move`
  - 写入活动练习走子事件，并在结束时归档。

## 归档与回顾数据流

### 在线对局

1. 用户登录。
2. 创建或加入房间。
3. 房间开始后创建活动对局记录。
4. 每步走子写入活动事件表，并更新活动快照。
5. 对局结束时生成 `game_archive` 与 `review_record`。
6. 历史页、个人页、排行榜、回顾页都读取归档数据。

### 练习局

1. 用户登录并创建练习局。
2. 练习局运行时持续写活动快照与走子事件。
3. 结束或主动退出时生成 `practice_archive`。
4. 练习统计进入个人页；回顾页可直接回放该归档。

## 安全要求

- 所有认证输入必须做 schema 校验。
- 密码必须哈希存储，不写明文，不可逆。
- 会话必须使用 `httpOnly` cookie。
- 所有写操作都通过服务端会话识别用户。
- 历史页与个人页接口默认只允许访问当前用户完整数据。
- 排行榜只暴露必要公开字段，不返回会话或敏感用户信息。

## 错误处理

- 未登录访问受限能力时，返回明确的 401/403，并在前端引导登录。
- 找不到归档时，回顾页显示空状态，不展示模糊错误。
- 排行榜或历史查询失败时，页面保留结构和重试入口。
- 数据写库失败时，不应伪装成成功；活动态与持久化态的失败要可观测。

## 测试策略

### 服务端

- 认证：注册、登录、登出、无效凭证。
- 会话：cookie 生效、未登录拒绝写操作。
- 归档：在线局结束后生成 archive；练习局结束后生成 archive。
- 回顾：归档可读取、步进回放数据完整。
- 排行榜：基础积分聚合正确。

### 前端

- 登录/注册表单交互。
- 登录后进入个人页。
- 历史页过滤。
- 回顾页步进与当前步同步。
- 排行榜页棋种切换。

### 验收链路

至少跑通一条真实完整链路：

1. 注册账号。
2. 登录。
3. 创建练习局或在线局并完成一盘。
4. 在个人页看到记录。
5. 在历史页看到归档。
6. 进入回顾页完成回放。

## 风险与取舍

- 若本轮同时引入数据库、认证、排行榜、回顾页，跨度较大，必须拆成明确任务顺序。
- 活动态持久化和活动态恢复不是同一个问题；首版优先解决“数据不丢”和“历史可查”，不强行做“中断后继续对局”。
- 回顾页若一开始追求深度分析，会拖慢整个基础设施闭环，应后置到下一轮。
- 排行榜首版用简单积分体系更可控，后续若切 Elo，需要迁移历史统计口径。
