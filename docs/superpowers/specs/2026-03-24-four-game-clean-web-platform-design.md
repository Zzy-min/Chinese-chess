# 四棋综合棋站清新版设计

## 概要

在现有 `XiangqiGame` 的三棋经验基础上，新建一个 `Node/TypeScript` 模块化网站，统一承载中国象棋、五子棋、围棋、国际象棋四种棋类的在线对局、AI 练习、学习、回顾能力。

本版设计的额外优先级：

- UI 必须清新、轻量、克制，避免厚重游戏化装饰。
- 高频交互必须快响应，先给用户明确反馈，再由服务端确认。
- 中国象棋与国际象棋棋盘必须在视觉和交互语言上明确区分，不能只换标题或资源。

## 产品边界

首版范围：

- 在线对局：四棋统一进入大厅，采用房间 + 邀请模式。
- AI 练习：四棋都可创建单人练习局。
- 学习：四棋都提供题库/残局入口、练习记录、最近错题。
- 回顾：在线局、练习局、学习尝试都可进入回顾页，支持步进回放和关键点评注。
- 个人页：战绩、练习统计、学习进度、收藏局面。

本版不包含：

- 自动匹配队列。
- 课程中心、长文教程、章节学习路径。
- 全量逐步深度 AI 分析。

## 技术方向

保留现有 Java 仓库作为规则和交互经验来源，但新主站不继续堆在 Java Web 服务中，而是建立新的 `Node/TypeScript` monorepo。

结构：

- `apps/web`：Next.js 主站。
- `apps/server`：Fastify API + WebSocket 服务。
- `packages/core`：四棋共享类型、事件协议、目录配置。
- `packages/engines-*`：四棋规则/AI 适配层。

关键原则：

- 服务端是唯一裁判端。
- 前端做乐观更新，但不拥有最终规则判定权。
- WebSocket 只用于在线多人对局。
- AI 练习和学习尝试先走 HTTP，减小实时复杂度。

## 四棋抽象

统一定义：

- `GameType`
- `GameCatalogEntry`
- `RulesAdapter`
- `PracticeAdapter`
- `ReviewAdapter`
- `NotationCodec`
- `BoardTheme`

棋种差异下沉到适配器和 renderer，不在页面层散落条件分支。

## UI / 交互设计

### 站点风格

- 明亮浅色背景。
- 细边框、轻阴影、圆角卡片。
- 清晰留白和分组。
- 减少沉重纹理和拟物装饰。

### 棋盘差异

中国象棋：

- 九宫格、楚河汉界、交叉线落子。
- 圆形汉字棋子。
- 坐标和提示按中式习惯表达。

国际象棋：

- 黑白格棋盘。
- 西洋棋图形棋子。
- `a-h` / `1-8` 坐标。
- 升变、将军、王车易位等提示按国际象棋习惯表达。

### 快响应要求

- 走子操作先本地反馈，再服务端确认。
- 页面切换和回顾步进采用局部更新，不整页刷新。
- 长棋谱回放按增量渲染。
- AI 点评异步生成，回顾页先可回放，再补充点评。

## 数据模型

首版统一数据表：

- `users`
- `sessions`
- `rooms`
- `games`
- `game_players`
- `game_moves`
- `practice_games`
- `learning_sets`
- `learning_attempts`
- `review_annotations`
- `saved_positions`

## 风险与约束

- 从 Java 迁移到 Node/TS 的工程量大于一次普通功能开发，必须按模块递进。
- `chess.js` 只解决国际象棋规则，不提供 AI。
- 围棋仍应保留独立引擎服务思路，避免把重推理塞进 Web 进程。
- UI 如果与性能冲突，以流畅和清晰优先。
