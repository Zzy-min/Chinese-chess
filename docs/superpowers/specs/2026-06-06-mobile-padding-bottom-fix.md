# 规格设计：移动端底部导航遮挡与滚动间距修复

本设计旨在修复“轻棋局”移动端页面在滑动到最底部时，内容被固定定位的底部导航栏（`.bottomNav`）遮挡的问题。

---

## 1. 现状与问题分析

1. **内容遮挡缺陷**:
   - 在手机窄屏下，底部导航栏 `.bottomNav` 采用固定定位（`position: fixed; bottom: 0;`），高度为 `60px`。
   - 现有的移动端响应式样式中，页面包裹层 `.shell` 仅设置了 `padding: 8px !important;`。
   - 当用户滚动到页面最底部时，底部的 52px 内容（如排行榜的“查看全部”按钮、快捷入口底部的卡片标题）会与固定在底部的导航栏重叠，导致这部分内容永久被遮挡，且无法通过继续向上滚动使其完全露出。
2. **截屏渲染伪影 (Artifact)**:
   - 在进行 FullPage 全屏截图时，Playwright 仿真视口被纵向拉长，这会导致固定定位的 `.bottomNav` 被渲染在页面中间（原 844px 视口高度处），遮挡了“快捷入口”的卡片标题。

---

## 2. 解决方案设计

### 2.1 CSS 样式修正 (app.css)
在 `@media (max-width: 768px)` 媒体查询中，为页面容器 `.shell` 增加底部的安全边距：
- 将 `.shell` 的 `padding` 从 `8px !important` 升级为 `8px 8px 80px 8px !important`。
- 多出的 `80px` 底部内边距不仅能完全抵消 `.bottomNav` 的 `60px` 高度，还保留了 `20px` 的视觉留白，确保所有底部可交互元素均能完全滑出导航栏并被用户正常点击。

### 2.2 测试截屏优化 (test_mobile_layout.js)
为了彻底消除全屏截屏时固定定位元素的干扰，更新 Playwright 验证逻辑：
- 在捕获全屏大厅主页前，通过 `page.evaluate()` 临时隐藏 `.bottomNav` 节点，确保生成的大图排版清晰，无元素重叠。
- 随后恢复显示以确保其状态完整。

---

## 3. 验收标准
- 重新验证后，生成的大厅首页全图不再有浮在中间的底部导航栏，展示出清晰完整的四大快捷入口卡片。
- 在移动端下，页面滚动到最底部时有充足的留白，所有底端操作按钮（如排行榜“查看全部”）完全显露。
