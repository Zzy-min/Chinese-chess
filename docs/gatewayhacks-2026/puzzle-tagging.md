# 残局标签与推荐规则

## 第一版标签

每道参赛题至少具有以下字段：

- `id`：现有学习目录中唯一且稳定的 ID。
- `difficulty`：`beginner | intermediate | advanced`。
- `skills`：从 `check_defense, safe_capture, piece_safety, forcing_move, basic_mate` 中选 1–3 个。
- `goal`：一句可验证的学习目标，不包含泛化战略判断。
- `maxMoves`：完成题目的最大人类走棋数。
- `assessmentSet`：`none | pre | post`；前后测题不得在自适应训练中出现。

## 错误类别到技能映射

| 错误类别 | 薄弱技能 | 推荐优先级 |
|---|---|---:|
| `missed_defense` | `check_defense` | 最高 |
| `hanging_piece` | `piece_safety` | 高 |
| `missed_capture` | `safe_capture` | 高 |
| `illegal_move` | 当前题技能 + 基础规则 | 中 |
| `neutral` | 不累计薄弱项 | 无 |
| `strong_move` | 降低对应技能错误权重 | 无 |

## 推荐算法

1. 校验错误统计键和值、已完成 ID 数量和题目目录存在性。
2. 按最近三类非零错误选择最高权重技能；相同权重时优先最近发生者。
3. 排除当前题、前后测题和已完成题，从相同难度且匹配技能的题中稳定排序选择。
4. 无匹配题时选择同难度未完成题；仍为空时允许复习最久未做的已完成题。
5. 返回选题原因，例如“你最近两次出现棋子未受保护，下一题练习子力安全”。
6. 不使用用户名、正式战绩、排行榜或人口属性参与推荐。

## 确定性反馈约束

- 只基于合法性、将军状态、固定棋子价值、一步内可验证的吃子关系和当前引擎推荐。
- 同一局面与同一走法必须产生相同类别和原因顺序。
- 引擎建议无法生成、不是合法走法或信号冲突时，省略建议并返回 `neutral`。
- 模板用简明中文，先陈述事实，再解释影响，最后给出可执行建议。
